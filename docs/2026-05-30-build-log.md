# SHUMap v2 架构记录

最后更新：2026-08-01 CST

## 当前状态

本轮工作在本地未提交代码上完成 v2 数据统一，未执行部署或远程数据库操作。

核心系统由以下部分组成：

- Cloudflare Worker：`worker/index-v2.ts`
- D1 迁移：`migrations-v2/`
- R2：地图资产、媒体与不可变发布产物
- Durable Object：发布串行协调
- Queue：地图导入任务

发布指针由 D1 的 release activation 数据维护。Worker 读取同一条 active release 记录，管理端与公开端共享这条权威来源。

## 统一分类

地图 chip 存于 `map_filter_categories`，成员存于 `map_filter_members`。成员支持三种互斥目标：

1. 地点类型 `place_kind_id`
2. 设施类型 `facility_type_id`
3. 商户集合 `includes_merchants=1`

地点通过 `places.kind_id` 归类，设施通过 `facility_instances.facility_type_id` 归类。使用中的目标必须指向启用中的 chip。`0012_map_filter_integrity.sql` 对新建、启用、移动、停用和删除操作提供数据库约束。

## 地图要素绑定

校区 SVG 元素在导入时写入 `map_features.source_element_id`。地点图形链路如下：

```text
place
  -> entity_locations
  -> location_anchors
  -> map_features
  -> map_versions
```

`location_anchors.map_feature_id` 与 `map_version_id` 必须对应同一地图版本。发布快照输出结构化位置数据，前端按 feature id 渲染和交互。

## 内容与审核

地点、设施和商户使用完整 `structure_json`：

- 地点结构包含 `kindId`、`aliases`、`building` 与 `locations`。
- 设施结构包含 `facilityTypeId`、`operationalStatus` 与 `locations`。
- 商户结构包含空间层级字段与 `locations`。

创建修订、提交审核和批准落库都会验证结构及分类归属。持久化 JSON 使用严格解析，字段缺失或类型错误会终止操作。
